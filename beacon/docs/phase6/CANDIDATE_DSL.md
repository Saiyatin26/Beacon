# BEACON Phase 6 — Candidate Domain Specific Language (DSL) Specification

This document provides the formal grammar, evaluation semantics, and syntax rules for all candidate rule expressions generated by Phase 6 discovery generators and evaluated by the `CandidateValidator`.

---

## 1. Core Principles

1. **Deterministic Syntax**: Every expression is human-readable, machine-parseable, and strictly canonicalized.
2. **3-Valued Truth Model**: Expressions evaluate against an `ObservationFact` into one of three states:
   - `True` (SUPPORT): The observation explicitly validates the invariant.
   - `False` (CONTRADICTION): The observation explicitly violates the invariant.
   - `None` (UNKNOWN / NOT APPLICABLE): The observation lacks necessary fields, is malformed, or has non-applicable structure.
3. **Domain Agnostic**: Expressions operate over generic field paths (`input.<field>`, `output.<field>`, `state_before.<tbl>.<field>`, `state_after.<tbl>.<field>`, `workflow.event('<name>')`, `has_error`).

---

## 2. Formal Grammar Table

| Category | Canonical Syntax Template | Example Expression | Evaluator Behavior |
| :--- | :--- | :--- | :--- |
| **Linear Formula** | `output.<f_out> == <a> * input.<f_in> [+/- <b>]` | `output.y == 2.0 * input.x + 5.0` | Checks `\|actual_out - (a * in + b)\| < numeric_tolerance` |
| **Direct Copy** | `output.<f_out> == input.<f_in>` | `output.user_id == input.user_id` | Checks strict equality between input and output fields |
| **Constant Output** | `output.<f_out> == <literal>` | `output.status == 'SUCCESS'` | Checks field matches literal (`string`, `number`, `bool`) |
| **Type Invariant** | `typeof(output.<field>) == '<type>'` | `typeof(output.amount) == 'number'` | Matches primitive type (`integer`, `number`, `string`, `boolean`, `array`, `object`) |
| **Output Shape** | `keys(output) == ['<k1>', '<k2>', ...]` | `keys(output) == ['id', 'status', 'total']` | Checks exact sorted key set of output object |
| **Field Presence** | `exists(output.<field>)` | `exists(output.transaction_id)` | Checks field is explicitly present in output mapping |
| **Non-Nullability** | `output.<field> != null` | `output.token != null` | Checks field is present and value is not `None`/`null` |
| **Relational Comparison** | `<z1>.<f1> <= <z2>.<f2>` / `>=` | `input.min_val <= output.max_val` | Compares numeric values across input/output scopes |
| **Error Status** | `has_error == false` / `has_error == true` | `has_error == false` | Checks explicit error observation flag |
| **Error Category** | `error.category == '<cat>'` | `error.category == 'VALIDATION_ERROR'` | Matches structured error category when error is observed |
| **State Mutation Flag** | `state.mutated == false` / `true` | `state.mutated == false` | Checks explicit state mutation observation |
| **State Table Row Count** | `state_after.<tbl>.row_count == state_before.<tbl>.row_count [+/- <delta>]` | `state_after.users.row_count == state_before.users.row_count + 1` | Compares table row count in before/after snapshots |
| **State Scalar Delta** | `state_after.<f> == state_before.<f> [+/- <delta>]` | `state_after.balance == state_before.balance - 50.0` | Compares scalar state fields across snapshot transition |
| **Workflow Event Ordering** | `workflow.event('<e1>') precedes workflow.event('<e2>')` | `workflow.event('auth') precedes workflow.event('exec')` | Verifies index of `e1` is less than index of `e2` in trace |
| **Workflow Sequence** | `workflow.sequence == [<e1> -> <e2> -> ...]` | `workflow.sequence == [init -> process -> finalize]` | Verifies entire execution trace matches exact sequence |
| **Cross-Input Invariant** | `cross_input_invariant(keys(output) == [...])` | `cross_input_invariant(keys(output) == ['id', 'val'])` | Verifies invariant holds across multiple distinct input signatures |
| **Cross-Input Monotonicity** | `monotonic_non_decreasing(input.<f_in> -> output.<f_out>)` | `monotonic_non_decreasing(input.score -> output.rank)` | Verifies output never decreases as input increases across input set |
| **Boundary Transition (Error)** | `transition(input.<f> >= <T>) -> has_error == <bool>` | `transition(input.age >= 18) -> has_error == false` | Verifies partition boundary where behavior shifts |
| **Boundary Transition (Output)**| `transition(input.<f> >= <T>) -> output.<f_out> == <literal>` | `transition(input.score >= 90) -> output.grade == 'A'` | Verifies output value shifts at numeric threshold $T$ |

## 3. Evaluation Rules & Invariants

1. **No Code Execution**: Discovered expressions are never evaluated with `eval()` or `exec()`. Evaluation occurs through deterministic AST/regex parsers and type-safe extractors in `CandidateValidator`.
2. **Missing Facts produce `None` (Unknown)**: If a fact lacks the referenced field, or if evidence was not captured (`is_valid=False`, `capture_status != CAPTURED`), the evaluation yields `None`. It is neither support nor contradiction.
3. **Contradictions are Explicit**: An observation only registers a contradiction if the referenced fields are present, valid, and their values actively disagree with the predicate.
4. **Commutative Normalization**: Symmetrical expressions (e.g. `output.a == output.b`) are normalized to standard lexicographical ordering before fingerprinting (`output.a == output.b`).

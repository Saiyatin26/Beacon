# BEACON V2 — Phase 6: Evidence Contract & Normalization Semantics

## 1. Overview
Phase 6 consumes Phase 3 execution evidence (`EvidenceBundle`) and transforms it once into a strongly typed, 3-valued `ObservationMatrix`.

The primary invariant of the Phase 6 evidence contract is:
> **Evidence status fails closed; model defaults never masquerade as observed facts; missing data yields UNKNOWN, never false support or false contradiction.**

---

## 2. Capture Status Normalization Matrix

| Capture Status | Normalized State | Observation Validity (`is_valid`) | Candidate Evaluation Impact |
| :--- | :--- | :--- | :--- |
| `CAPTURED` | `CAPTURED` | `True` | Normal 3-valued evaluation (Support / Contradiction / Inapplicable) |
| `PARTIAL` | `PARTIAL` | `False` | Evaluates to `UNKNOWN` (Increments `unknown_count`) |
| `FAILED` | `FAILED` | `False` | Evaluates to `UNKNOWN` (Increments `unknown_count`) |
| `NOT_AVAILABLE` | `NOT_AVAILABLE` | `False` | Evaluates to `UNKNOWN` (Increments `unknown_count`) |
| `NOT_SUPPORTED` | `NOT_SUPPORTED` | `False` | Evaluates to `UNKNOWN` (Increments `unknown_count`) |
| `UNKNOWN` | `UNKNOWN` | `False` | Evaluates to `UNKNOWN` (Increments `unknown_count`) |
| *Any unrecognized string/enum* | `UNKNOWN` (Fail-Closed) | `False` | Evaluates to `UNKNOWN` (Increments `unknown_count`) |

---

## 3. Model Defaults vs Observed Facts

To prevent model defaults (e.g. `has_error = False` or `state_mutated = False` or `row_count = 0`) from falsely generating rules:

1. **`has_error` (`Optional[bool]`)**:
   - `True`: Error record present, non-zero exit code, or HTTP status $\ge 400$.
   - `False`: Output explicitly observed with exit code $0$ or HTTP status $< 400$ without error records.
   - `None`: Error status was not observed / missing.
   - `error_observed`: Boolean flag indicating whether error status was observed.

2. **`state_mutated` (`Optional[bool]`)**:
   - `True`: State snapshot before $\neq$ state snapshot after.
   - `False`: State snapshot before $=$ state snapshot after.
   - `None`: State snapshots were missing, malformed, or uncaptured.
   - `state_observed`: Boolean flag indicating whether valid Phase 3 state evidence was present.

3. **`output_observed` (`bool`)**:
   - `True`: Output payload was observed.
   - `False`: Output was absent.

---

## 4. Evidence-Backed Candidate Provenance
Every candidate generated by Phase 6 maintains:
- `discovery_method`: Mining algorithm (e.g., `formula_fitting`, `cross_input_analysis`, `state_delta_analysis`, `boundary_analysis`).
- `input_ids`: List of specific input IDs supporting the candidate.
- `evidence_ids`: List of Phase 3 evidence record IDs backing the candidate.
- `fingerprint`: Cryptographic SHA-256 digest of `rule_type`, `role_scope`, `canonical_expression`, and variables.
